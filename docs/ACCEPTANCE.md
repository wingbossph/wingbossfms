# Acceptance criteria: how each one is shown

Each criterion from the spec (section 11) has automated tests, plus steps to see it in the app with the demo data (`npm run db:seed:demo`).

| # | Criterion | Automated test | Try it |
|---|---|---|---|
| 1 | A Lanang cashier logs in with a PIN, imports Loyverse or enters sales with a payment split across cash, Maya, GCash 1/2, BPI and Grab, closes the shift with a cash count, and can't see Matina or any profit figure. | e2e `phase1-foundation` (PIN login, Lanang only, no Dashboard/Reports/Payroll, `/forbidden` everywhere else) and `phase2-sales` (sales entry, split payments, shift close, Loyverse import); integration `sales-cash` | Register a tablet for Lanang (Admin → Devices), log out, PIN 4001. Enter sales, split the payments, submit, close the shift. |
| 2 | Commissary records a sauce batch and dispatches it to Lanang; Lanang confirms; Lanang's COGS goes up; the commissary statement shows the transfer value. | integration `inventory-commissary` (batch cost from the recipe, dispatch, receipt, Lanang inventory → COGS at count, statement); e2e `phase5-commissary` | Commissary → Production → Dispatch; Commissary → Transfers → confirm as Lanang; Commissary → Statement. |
| 3 | P&L for Matina only, Lanang only, Commissary only and consolidated; consolidated = sum of the locations, inter-company eliminated. | integration `ledger-statements` (consolidated profit = sum of the locations); inter-location accounts are flagged and left out of consolidated columns; e2e `phase4-ledger` | Reports → Profit & loss → *By location* shows each location and *Consolidated*. Pick one location in the filter for a single-location P&L. |
| 4 | The dashboard shows money in by channel for any range, matching the sales entries exactly. | integration `dashboard` (bucket totals, personal GCash share, tie-out to the sales-by-channel report); e2e `phase8-dashboard` | Dashboard → change the period/location. Compare with Reports → Sales by payment channel. |
| 5 | A bank CSV auto-matches at least 80% of lines on the sample data; the reconciliation reaches ₱0. | integration `banking` (≥ 80%, payout at the real MDR, ₱0, lock, undo); unit `banking`; demo statement matches ~99% | Banking → Import statement → `samples/bpi-statement-demo.csv` into BPI Bank. Book the service charges/interest from the statement, *Mark cleared* the opening balance, then Reconcile → Complete & lock. |
| 6 | The variance report flags a day when wings per pax was 15% over standard. | integration `inventory-commissary` (a 15% day is flagged, the 0% day isn't) | Inventory → Variance for Matina: one day in the demo is flagged at +15%. |
| 7 | A fourth branch takes one form and shows in every report without code changes. | e2e `phase1-foundation` ("owner adds a new branch in one form and it appears everywhere") | Admin → Locations → Add. It appears in every location filter, the P&L columns, the dashboard and the DTR. |
| 8 | Every report exports to PDF and Excel with correct totals. | e2e `phase4-ledger`, `phase8-dashboard` (every new report exports), `phase7-payroll` (register Excel, payslip PDF); exports render the same `ReportDoc` as the screen | Any report → Excel / PDF / CSV buttons. |
| 9 | The audit log shows who changed an expense amount, with before/after values. | integration `expenses` (an approver's amount correction is logged with before/after totals); e2e `phase1-foundation` (before/after on a user in the audit log screen), `phase3-expenses` (approval in the audit log) | Change an expense's amount, then Admin → Audit log. |
| 10 | All accounting unit tests pass; the trial balance always balances. | unit tests (ledger lines, money, WAC, payroll); the posting integration tests (sales, expenses, inventory, banking, payroll, migration) assert the trial balance difference is 0; DB trigger rejects unbalanced entries | Reports → Trial balance shows "Debits equal credits ✓". |
